# ЮKassa: как подключить оплату (пошагово)

Инструкция только про вариант `PAYMENTS_MODE=yookassa` — когда бот принимает карты и СБП
через API ЮKassa, а деньги приходят на счёт магазина (в отличие от Telegram Stars).

## Как это работает

```
Клиент в боте            Бот                                  ЮKassa
───────────────────────────────────────────────────────────────────────────────
«Тарифы» → тариф    →  POST /v3/payments (shopId + ключ)
                         Idempotence-Key = номер заказа
                                          ──────────────►  платёж создан (pending)
                      ◄───────────  confirmation_url
присылает             →  сообщение со ссылкой «Оплатить»
оплачивает  ──────────────────────►  страница оплаты ЮKassa (карта / СБП)
                                          ──────────────►  платёж succeeded
                                          ◄──────────────  вебхук payment.succeeded
                       перепроверяет: GET /v3/payments/{id}
                       сверяет сумму с заказом
                       выдаёт/продлевает клиента в 3x-ui
                      →  отправляет клиенту ключ vless://…
```

Важные свойства:

- **Ключ выдаётся только после подтверждённой оплаты.** Тело вебхука не считается
  доказательством: бот сам переспрашивает платёж в API ЮKassa и проверяет сумму.
- **Повторные вебхуки безопасны**: подписка не продлевается дважды (номер платежа
  фиксируется в заказе и в комментарии клиента панели).
- **Есть резервный путь**: кнопка «🔄 Проверить оплату» в сообщении со счётом — работает,
  даже если вебхук не дошёл.

## Шаг 0. Что понадобится

- Аккаунт ЮKassa (регистрация на [yookassa.ru](https://yookassa.ru/), вход через Яндекс ID).
- **Тестовый магазин** — доступен сразу после регистрации и заполнения анкеты, договор для
  теста не нужен, деньги никуда не переводятся.
- Сервис на Railway (бот уже умеет принимать вебхуки: поднимает `/healthz` и
  `/yookassa/webhook` на порту `PORT`).

## Шаг 1. Тестовый магазин и ключи API

1. Личный кабинет ЮKassa → **Интеграция → Ключи API**.
2. Скопируйте:
   - **shopId** — номер магазина (число, например `123456`);
   - **секретный ключ** тестового магазина — он начинается с `test_`.
3. В тестовом режиме доступны оплата картой и кошельком ЮMoney — для проверки интеграции
   этого достаточно.

Боевые ключи (после активации магазина) выглядят так же, только секретный ключ начинается
с `live_` (в старых кабинетах — произвольная строка), а shopId — номер боевого магазина.

## Шаг 2. Публичный адрес на Railway

1. Railway → ваш сервис → **Settings → Networking → Generate Domain**.
2. Получите адрес вида `https://ваш-сервис.up.railway.app`.

Бот сам подставляет его из `RAILWAY_PUBLIC_DOMAIN`, поэтому адрес вебхука —
`https://ваш-сервис.up.railway.app/yookassa/webhook`. Отдельный веб-сервер поднимать не нужно:
бот запускает его сам и слушает `PORT`, который Railway передаёт автоматически.

Требования ЮKassa к адресу уведомлений: **HTTPS**, порт **443** (или 8443), TLS **1.2+**.
Домен Railway подходит.

## Шаг 3. Переменные в Railway (Variables)

| Переменная | Значение | Обязательно |
|---|---|---|
| `PAYMENTS_MODE` | `yookassa` | да |
| `YOOKASSA_SHOP_ID` | `123456` (shopId тестового магазина) | да |
| `YOOKASSA_SECRET_KEY` | `test_xxxxx…` | да |
| `YOOKASSA_TEST` | `1` | рекомендуется (включает пометку «тестовый магазин» в подсказках) |
| `YOOKASSA_VAT_CODE` | `0` | по умолчанию `0` — чек не передаём, см. шаг 8 |
| `YOOKASSA_OAUTH_TOKEN` | `token_…` | нет — нужен только для автонастройки вебхука |
| `PUBLIC_BASE_URL` | `https://ваш-сервис.up.railway.app` | нет — на Railway подставляется сам |
| `PORT` | Railway задаёт сам | нет |

После сохранения переменных Railway перезапустит сервис.

## Шаг 4. Вебхук — самый важный шаг

При обычной авторизации (shopId + секретный ключ, Basic Auth) ЮKassa разрешает настраивать
уведомления **только в личном кабинете** — через API это можно делать лишь по OAuth-токену.
Поэтому:

1. ЮKassa → **Интеграция → HTTP-уведомления** → «Изменить настройки».
2. В поле URL укажите `https://ваш-сервис.up.railway.app/yookassa/webhook`.
3. Включите событие **`payment.succeeded`** (при желании — `payment.canceled`).
4. Сохраните.

Что должно быть в ответе бота: HTTP 200. Если ответа нет или он не 200, ЮKassa повторяет
уведомление в течение 24 часов; бот в ответе на вебхук всегда перепроверяет платёж в API,
поэтому «лишние» повторы не приведут к двойной выдаче.

> **Автонастройка (необязательно).** Если у вас есть OAuth-токен ЮKassa (партнёрская
> программа), добавьте `YOOKASSA_OAUTH_TOKEN=token_…` — бот сам зарегистрирует вебхук в API
> при старте и не станет дублировать уже существующий.

> **Вебхук не обязателен для выдачи.** Даже без него в сообщении со счётом есть кнопка
> «🔄 Проверить оплату»: бот по нажатию спросит статус платежа в API и сразу выдаст ключ.
> Но с вебхуком ключ приходит автоматически, без действий клиента.

## Шаг 5. Проверьте настройки в боте

- `/panel_debug` (админ) → пункт **«Оплата»**: режим, shopId, наличие ключа, адрес вебхука
  и подсказка, куда его добавить.
- `/payments` (админ): режим, выручка, последние заказы; в строке вебхука будет
  «(автонастройка ✅)» при OAuth-токене или «(добавляется в кабинете ЮKassa)» без него.
- `/start` → «Тарифы» — цены теперь показываются в рублях.

## Шаг 6. Тестовая оплата

1. В боте: `/start` → «💰 Тарифы» → выберите тариф → бот пришлёт сообщение со ссылкой
   «Оплатить 149 ₽» (цена зависит от тарифа) и кнопкой «Проверить оплату».
2. Нажмите «Оплатить» — откроется страница ЮKassa. Введите тестовую карту:

**Успешные сценарии**

| Номер карты | Тип |
|---|---|
| `5555 5555 5555 4477` | Mastercard с 3-D Secure (основная тестовая) |
| `5555 5555 5555 4444` | Mastercard без 3-D Secure |
| `4111 1111 1111 1111` | Visa |
| `2200 0000 0000 0004` | Мир с 3-D Secure |

Срок действия — любой в будущем, CVC/CVV — любые 3 цифры, код 3-D Secure — любые 3 цифры.

**Неуспешные сценарии (проверить обработку отказов)**

| Номер карты | Что имитирует |
|---|---|
| `5555 5555 5555 4592` | не пройден 3-D Secure |
| `5555 5555 5555 4535` | банк отклонил платёж |
| `5555 5555 5555 4543` | карта просрочена |
| `5555 5555 5555 4600` | недостаточно средств |
| `5555 5555 5555 4568`, `…4634` | подозрение на мошенничество |

3. После успешной оплаты бот сам пришлёт ключ. Проверьте:
   - ключ `vless://…` пришёл и подключается;
   - `/profile` — подписка «Активна», срок из тарифа;
   - `/payments` — заказ в статусе «оплачен», сумма в выручке;
   - в панели 3x-ui есть клиент `tg-paid-<telegram_id>` с лимитами из тарифа.
4. Отказ карты: ключ не выдаётся, заказ остаётся неоплаченным, клиент может попробовать снова.

Повторные проверки (можно прогнать самому, чтобы убедиться в защите):
оплатить один счёт дважды, обновить страницу возврата, нажать «Проверить оплату» повторно —
подписка не должна продлиться больше одного раза.

## Шаг 7. Возвраты и блокировки

- Удалить подписку: `/revoke <telegram_id>` у бота (клиент `tg-paid-<id>` удаляется из панели).
- Вернуть деньги: ЮKassa → **Платежи** → нужный платёж → «Вернуть» (полный или частичный
  возврат). Сначала можно сделать `/revoke`, чтобы клиент не остался с доступом.

## Шаг 8. Переход в боевой режим

1. В ЮKassa активируйте магазин (договор, реквизиты), включите нужные способы оплаты
   (карты, СБП) — состав способов зависит от вашего договора.
2. Возьмите боевые ключи: **Интеграция → Ключи API** боевого магазина.
3. В Railway замените `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` на боевые, поставьте
   `YOOKASSA_TEST=0`.
4. Проверьте, что в кабинете по-прежнему указан адрес вебхука (он один для магазина).
5. Сделайте реальную оплату самого дешёвого тарифа и, если нужно, верните деньги из кабинета.
6. **Чек 54-ФЗ**: `YOOKASSA_VAT_CODE` по умолчанию `0` — чек не передаётся.
   - если чеки фискализирует ваша онлайн-касса — укажите ставку НДС: `1` (без НДС),
     `2` (0 %), `3` (10 %), `4` (20 %), `5` (10/110), `6` (20/120);
   - если чеки делает сам сервис («Чеки от ЮKassa») — оставьте `0`, ЮKassa сформирует их сама;
   - если фискализации нет — оставьте `0`, иначе создание платежа может падать с ошибкой.

## Частые проблемы

| Симптом | Причина и что делать |
|---|---|
| `ЮKassa вернула ошибку HTTP 401: Basic auth failed` | Неверный `YOOKASSA_SHOP_ID`/`YOOKASSA_SECRET_KEY` или ключ от другого магазина. Скопируйте заново из кабинета |
| «ЮKassa недоступна…» в логах | Сервис не может выйти в интернет (редко на Railway) или опечатка в `YOOKASSA_API_URL` |
| Оплатил, ключ не пришёл | Нажмите «🔄 Проверить оплату». Если и это не помогло — проверьте адрес в «HTTP-уведомления» (шаг 4) и `/panel_debug` |
| Заказ «⏳ pending» спустя минуту после оплаты | Вебхук не настроен либо платёж ещё в обработке: подождите и нажмите «Проверить оплату» |
| `amount_mismatch` в логах | Сумма платежа не совпала с заказом — бот сознательно не выдаёт ключ (защита) |
| Тестовая карта не проходит | Магазин боевой или ключ не `test_`. Тестовые карты работают только в тестовом магазине |
| ЮKassa не принимает адрес вебхука | Нужен HTTPS на порту 443/8443; у домена Railway это уже так |
| Оплата прошла дважды по одному счёту | Второй платёж не выдаст второй ключ: защита по сумме и номеру заказа, лишнее верните в кабинете |

## Важно про правила Telegram

Продажа **цифровых товаров** (VPN-ключей) внутри Telegram по правилам мессенджера должна идти
через **Telegram Stars**. ЮKassa — отличный вариант, если оплата происходит вне Telegram
(сайт, лендинг, mini-app с собственным эквайрингом) или если товар не цифровой. Если торгуете
ключами именно в боте — используйте `PAYMENTS_MODE=stars`, а ЮKassa держите как дополнительный
канал; подробности — в README, раздел «Оплата подписок».
