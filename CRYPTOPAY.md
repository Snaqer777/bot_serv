# 💎 Оплата криптой через @CryptoBot (Crypto Pay API)

Инструкция для владельца сервиса: как принимать оплату в крипте (USDT/TON/BTC/…) и
автоматически выдавать VPN-ключ. Всё уже реализовано в `bot.py` — здесь только шаги настройки.

Коротко: **6 шагов до первой оплаты**, из них 4 обязательных. Денег для проверки не нужно —
см. раздел [«Как проверить выдачу ключа без денег»](#как-проверить-выдачу-ключа-без-денег).

```
1. @CryptoTestnetBot → /pay → My Apps → Create App      ← тестовое приложение (бесплатно)
2. Railway → Variables: CRYPTOBOT_TOKEN + CRYPTOBOT_ASSET + CRYPTOBOT_TEST=1
3. Проверить оплату тестовыми монетами (кнопка «Проверить оплату» выдаёт ключ)
4. @CryptoBot → /pay → My Apps → Create App              ← боевое приложение
5. Railway: заменить CRYPTOBOT_TOKEN, убрать CRYPTOBOT_TEST
6. (по желанию) включить Webhooks в приложении — быстрее приходит ключ
```

---

## 1. Что это и почему крипта

**@CryptoBot** — официальный бот мессенджера Telegram для крипто-платежей (это разные боты:
`@CryptoBot` — боевая сеть, `@CryptoTestnetBot` — тестовая). Внутри него есть раздел
**Crypto Pay** — платёжный API для ботов: приложение создаётся за пару минут, а бот получает
счёт `createInvoice` и подтверждение оплаты вебхуком или опросом API.

Что это даёт:

| | Крипта (Crypto Pay) | Telegram Stars | ЮKassa |
|---|---|---|---|
| Реквизиты | не нужны, только аккаунт Telegram | не нужны | нужен магазин + договор |
| Комиссия | сеть + комиссия CryptoBot | ~30 % при выводе через Fragment | 2.8–3.5 % или «Чеки» |
| Вывод денег | `transfer`/вывод прямо в CryptoBot, в рублях через P2P | Fragment → TON → P2P | на расчётный счёт по договору |
| Тестовый режим | да, `@CryptoTestnetBot` (тестовые монеты) | нет (только бой) | да, тестовый магазин |
| Кто может получить | любой | любой | ИП/ООО/самозанятый |
| Возвраты | вручную (крипта отправлена и необратима) | `refundStarPayment` | возврат в кабинете ЮKassa |

Главный плюс для тебя: **не нужны юрлицо, договор и фискализация** — приём крипты не
регулируется 54-ФЗ и не требует онлайн-кассы. Минус — платёж необратим, поэтому возвраты
делаются вручную (опционально: через кнопку `/revoke` и отправку крипты обратно).

> ⚠️ Про правила Telegram: оплата криптой идёт не встроенным платежом Telegram, а счётом
> в @CryptoBot (Mini App) — это внешний способ оплаты, поэтому правила Telegram про
> цифровые товары к нему напрямую не применяются. Если в будущем понадобится «нативный»
> способ внутри чата, верни Stars одной переменной (`PAYMENTS_MODE=stars`) — все настройки
> крипты при этом можно оставить как есть.

## 2. Шаг 1. Тестовое приложение в @CryptoTestnetBot (обязательно)

1. Открой **@CryptoTestnetBot** и напиши ему `/pay`.
2. Нажми **My Apps** → **Create App** → придумай название (например `VPN Shop Test`).
3. Скопируй **API Token** (строка вида `12345:AA...`).

Тестовая сеть — это настоящий API, но монеты «ненастоящие»: в этом же боте через
**Wallet → Deposit** можно получить тестовые USDT (кнопка в тестовом режиме бесплатная),
чтобы оплатить собственный счёт.

## 3. Шаг 2. Переменные в Railway

Railway → ваш сервис → **Variables**:

| Переменная | Значение | Обязательно |
|---|---|---|
| `CRYPTOBOT_TOKEN` | токен приложения из шага 1 (`12345:AA...`) | ✅ |
| `CRYPTOBOT_TEST` | `1` — тестовая сеть | ✅ на тесте |
| `CRYPTOBOT_ASSET` | `USDT` (по умолчанию), `TON`, `BTC`, `USDC`, `BUSD` | нет |
| `PAYMENTS_MODE` | `crypto` — можно не задавать: режим включится сам, если есть `CRYPTOBOT_TOKEN` | нет |
| `CRYPTOBOT_RUB_RATE` | курс вручную: сколько рублей стоит 1 единица валюты (например `95`). Если не задавать — бот берёт курс у Crypto Pay | нет |
| `CRYPTOBOT_INVOICE_TTL` | сколько секунд живёт счёт (по умолчанию `3600`) | нет |
| `CRYPTOBOT_POLL_INTERVAL` | как часто проверять оплату без вебхука, сек (по умолчанию `60`, минимум `15`) | нет |
| `CRYPTOBOT_API_URL` | адрес API (менять не нужно: бот сам выбирает тест/бой по `CRYPTOBOT_TEST`) | нет |
| `PAYMENTS_ALLOW_TEST_PAY` | `1` — разрешить проверку выдачи ключа без оплаты (`/test_pay`). В тестовой сети включается автоматически; после проверки лучше убрать | нет |

Нажми **Deploy** (Railway перезапустит сервис). Проверка: команда **`/panel_debug`** в боте →
пункт «Оплата»:

```
7. Оплата: крипта через @CryptoBot (crypto)
   Сеть: тестовая сеть 🧪 (CryptoTestnetBot)
   Токен приложения: задан ✅
   Валюта счёта: USDT
   Курс: берётся из Crypto Pay (getExchangeRates)
   Вебхук: https://ваш-домен/cryptobot/webhook
   Опрос API: каждые 60 сек (работает и без вебхука)
   Приложение: VPN Shop Test (app_id 12345, CryptoTestnetBot)
```

Если в строке «Приложение» ошибка `UNAUTHORIZED (401)` — токен неверный или взят от
`@CryptoBot` (боевой) при включённом `CRYPTOBOT_TEST=1`. Токены боевой и тестовой сети
**не взаимозаменяемы**.

## 4. Шаг 3. Тестовая оплата

1. В боте: **«💰 Тарифы»** → выбери тариф → бот пришлёт счёт с суммой в крипте
   (например `2.61 USDT` ≈ `249 ₽`) и кнопкой **«💳 Оплатить … USDT»**.
2. Нажми «Оплатить» — откроется `@CryptoTestnetBot` со счётом → оплати его тестовыми
   монетами (кнопка оплаты в тестовой сети бесплатная).
3. Вернись в бота: ключ выдастся сам (вебхук/опрос), либо нажми
   **«🔄 Проверить оплату»**. В сообщении появится `vless://…`, срок до даты и лимиты тарифа.

Проверь, что ключ реально работает: скопируй его в клиент (Happ/v2rayNG) и подключись.

Что проверяет сам бот (это уже покрыто тестами в `tests/test_payments.py`):

- ключ **не выдаётся** пока счёт не оплачен и после истечения срока счёта;
- сумма и валюта оплаченного счёта сверяются с заказом (подмена суммы → выдачи нет);
- вебхук с неправильной подписью → `401`, тело вебхука не считается доказательством —
  бот переспрашивает счёт через API;
- повторные вебхуки/опросы не продлевают подписку дважды;
- если панель 3x-ui недоступна, заказ помечается оплаченным, но не выданным: админу
  уходит алерт «оплата есть, ключ не выдан», а ключ выдастся при следующем подтверждении.

## 4.1. Как проверить выдачу ключа без денег

> В боевом режиме этих команд в боте нет: `/test_pay` и `/crypto_check` регистрируются только
> при `PAYMENTS_ALLOW_TEST_PAY=1` или в тестовой сети (`CRYPTOBOT_TEST=1`). Спрятать их даже
> в тестнете можно переменной `TEST_TOOLS=0`. Код при этом остаётся на месте — вернуть команды
> можно в любой момент, изменив переменную.

Платить вообще не обязательно: выдачу ключа можно проверить тремя способами, от самого
простого к самому полному.

### Способ 1. Проверка выдачи без оплаты — `/test_pay` (рекомендуется)

Бот проходит **ровно тот же путь**, что и после настоящей оплаты: создаёт заказ, клиента
`tg-paid-<telegram_id>` в 3x-ui, считает срок и лимиты из тарифа и присылает то самое
сообщение с ключом. Отличается только пометкой «тест»:

- деньги не списываются, счёт в Crypto Pay **не создаётся вообще**;
- заказ помечается тестовым и **не попадает в выручку** (`/payments`);
- внизу сообщения есть кнопка **«🗑 Удалить тестовую подписку»** — убирает тестовый ключ из панели;
- опрос оплат и вебхуки тестовый заказ не трогают.

Как включить и запустить:

1. Самый простой вариант — тестовая сеть: при `CRYPTOBOT_TEST=1` проверка включается сама.
2. В боевом режиме добавь в Railway переменную `PAYMENTS_ALLOW_TEST_PAY=1` (после проверки её
   лучше убрать, чтобы «бесплатных» выдач не осталось).
3. В боте: `/test_pay` — покажет кнопки тарифов, либо сразу `/test_pay basic`.
   Можно и из `/payments` → кнопка **«🧪 Проверить выдачу ключа без оплаты»**.
4. Проверь, что ключ появился в панели 3x-ui и открывается в клиенте (Happ/v2rayNG).
5. Нажми **«🗑 Удалить тестовую подписку»** — бот уберёт клиента и пометит заказ отменённым.

Безопасность: команда доступна **только администратору** (`ADMIN_ID`, можно перечислить нескольких
через запятую: `111,222`); если у аккаунта уже есть
настоящая платная подписка, проверка откажется её трогать и предложит `/revoke` — чтобы тест
не перезаписал метку реального платежа. Кнопка удаления снимает только ту подписку, которая
выдана тестовым заказом: настоящий ключ она не тронет.

### Способ 2. Проверка связки с Crypto Pay — `/crypto_check`

Проверяет, что интеграция с Crypto Pay настроена правильно, **не создавая долгов**: бот
обращается к API, считает курс, создаёт счёт на минимальный тариф и тут же удаляет его
(`deleteInvoice`). Платить по такому счёту не нужно, в выручку он не попадает.

```
🔍 Проверка Crypto Pay — тестовая сеть 🧪 (CryptoTestnetBot)
• Приложение: VPN Shop (app_id 12345)
• Обрабатывающий бот: @CryptoTestnetBot
• Курс: 1 USDT = 95.5 ₽ (из Crypto Pay)
• Создание счёта: ✅ 1 на 2.61 USDT (≈ 249 ₽)
• Удаление счёта: ✅ счёт удалён, платить по нему не нужно
```

Команда `/crypto_check` (тоже только для админа) отвечает и на вопросы «токен правильный?»,
«валюта поддерживается?», «курс отдаётся?» — это первое, что стоит запустить после настройки
переменных. Если в тестовой сети ты случайно взял боевой токен (или наоборот), увидишь
`UNAUTHORIZED (401)` с подсказкой.

### Способ 3. Полный прогон с бесплатными тестовыми монетами

Если хочется пройти именно настоящую оплату (ссылка → кошелёк → вебхук), в тестовой сети
монеты бесплатные:

1. **@CryptoTestnetBot** → раздел **Wallet** → **Deposit**: в тестовой сети пополнение
   бесплатное, монеты не имеют стоимости и не выводятся (это песочница). Удобнее всего
   USDT или TON.
2. Создай счёт в боте, открой его и оплати тестовыми монетами — ключ придёт так же, как
   при настоящей оплате (вебхук или опрос API).
3. Если внутри бота оплатить не получается — в счёте есть адрес для перевода: отправь
   на него нужную сумму тестовых монет из кошелька тестовой сети, оплата подтвердится так же.

### Способ 4. Локальные тесты (без сервера и панели вообще)

В репозитории лежит полный прогон оплаты на фейковых API — от создания счёта до выдачи ключа
в фейковой 3x-ui:

```bash
pip install -r requirements.txt pyotp
python tests/test_payments.py
```

Здесь проверяются все четыре режима оплаты (Stars, BotFather, ЮKassa, Crypto Pay), подделка
подписи вебхука, подмена суммы, дубли, сбои панели и недоступность провайдера. 262 проверки,
реальные деньги и реальные сервисы не нужны.

| Способ | Что проверяет | Нужны деньги |
|---|---|---|
| `/test_pay` | выдачу ключа в реальной панели + текст сообщения | нет |
| `/crypto_check` | токен, сеть, курс, создание и удаление счёта | нет |
| Оплата тестовыми монетами | весь путь целиком, включая вебхук | нет (тестовые монеты) |
| `tests/test_payments.py` | всю логику бота на фейковых API | нет |

## 5. Шаг 4. Боевое приложение в @CryptoBot

Повтори то же самое с **@CryptoBot**: `/pay` → **My Apps** → **Create App** → скопируй
API Token. В Railway замени:

- `CRYPTOBOT_TOKEN` — на боевой токен;
- `CRYPTOBOT_TEST` — удали (или поставь `0`).

После деплоя `/panel_debug` должен показать «Сеть: основная сеть (CryptoBot)».

> 💰 Где взять крипту для выплат: крипта от покупателей копится на балансе приложения
> внутри @CryptoBot (раздел My Apps → твоё приложение → Balance). Вывод — кнопкой
> **Withdraw**/`transfer` на любой кошелёк или на баланс @CryptoBot, а оттуда через
> **Wallet → Sell/P2P** можно вывести в рубли/фиат. Комиссии смотри в разделе Wallet.

## 6. Шаг 5. Вебхуки (необязательно, но быстрее)

Без вебхука оплата подтверждается **опросом API** каждые `CRYPTOBOT_POLL_INTERVAL` секунд —
работает так же надёжно, просто ключ может прийти на минуту позже. Чтобы ключ приходил
мгновенно:

1. Railway → Settings → Networking → **Generate Domain** (если ещё не сделал) — получишь
   `https://ваш-сервис.up.railway.app`.
2. Убедись, что `PUBLIC_BASE_URL` в Variables = этот домен (Railway обычно подставляет сам).
3. @CryptoBot → `/pay` → **My Apps** → твоё приложение → **Webhooks** → добавь URL:

```
https://ваш-сервис.up.railway.app/cryptobot/webhook
```

4. Убедись, что включено событие **invoice_paid** (Crypto Pay присылает только его).

Бот принимает вебхук на `/cryptobot/webhook` (есть алиас `/crypto/webhook`), проверяет
подпись `Crypto-Pay-Api-Signature` (HMAC-SHA256 с ключом `SHA256(API-токен)`) и всё равно
перепроверяет счёт через API — так что даже подобранный вебхук не выдаст ключ.

## 7. Как это работает в коде (для понимания)

```
payment_store (журнал заказов)                Crypto Pay API                3x-ui
      │                                              │                         │
  start_checkout ──► getExchangeRates (курс) ───────►│                         │
      │            ──► createInvoice (payload=order) ►│                         │
      │◄────────────── bot_invoice_url ───────────────┤                         │
      │  кнопка «Оплатить» + «Проверить оплату»       │                         │
      │                                               │                         │
  вебхук /cryptobot/webhook ──► проверка подписи      │                         │
      │        ──► getInvoices(invoice_id) ──────────►│                         │
      │◄────────────── status=paid, asset, amount ────┤                         │
      │  сверка суммы и валюты с заказом              │                         │
      └── fulfill_order ──────────────────────────────┼──► clients/add (ключ) ──►│
                                                      │
  crypto_payment_poller (каждые 60 с) ──► getInvoices(status=paid) ──► то же самое
```

Файлы/функции: `CryptoPayClient`, `crypto_amount_for_rub`, `cryptobot_rate`,
`crypto_invoice_matches`, вебхук `cryptobot_webhook`, `crypto_poll_once`,
`recheck_order_payment`, `fulfill_order`, `payment_store`.

## 8. Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `Не задан CRYPTOBOT_TOKEN` | переменная не добавлена или сервис не передеплоен |
| `UNAUTHORIZED (401)` | токен от другого бота/сети. Тест → `@CryptoTestnetBot` + `CRYPTOBOT_TEST=1`; бой → `@CryptoBot` без `CRYPTOBOT_TEST` |
| `Crypto Pay недоступен` | нет доступа в интернет/Railway засыпает; проверь `CRYPTOBOT_API_URL=https://pay.crypt.bot/api` |
| `Не удалось узнать курс USDT к рублю` | Crypto Pay не отдал курс — задай `CRYPTOBOT_RUB_RATE=95` (рублей за 1 единицу) |
| Счёт создан, но оплата не подтверждается | нажми «🔄 Проверить оплату»; если помогло — включи вебхук (шаг 5) или ждёт опрос (до 60 с) |
| «Сумма оплаты не совпала с заказом» | счёт оплачен не полностью (или в другой валюте) — выдача не делается, верни деньги вручную и попроси оплатить новый счёт |
| Хочу другую валюту | `CRYPTOBOT_ASSET=TON` (или `BTC`, `USDC`, …) и передеплой |
| Не хочу платить за проверку | `/test_pay <тариф>` — выдача ключа без оплаты (кнопка в `/payments`); `/crypto_check` — проверка токена и счёта без денег |
| `/test_pay` пишет «выключена» | включи `PAYMENTS_ALLOW_TEST_PAY=1` (в тестовой сети включается сама) |
| `/test_pay` отказывается работать | у аккаунта уже есть платная подписка — проверка не хочет её испортить: сначала `/revoke <id>` |
| «Команда доступна только администратору» | пришли `/myid`: бот покажет твой ID и что стоит в `ADMIN_ID`. Нужен именно числовой ID (не `@username`); несколько админов — через запятую |
| Цена в крипте получилась «некругой» | это округление **вверх** до точности валюты (USDT — 2 знака, BTC — 6). Ровные цены — при `CRYPTOBOT_RUB_RATE`, подобранном под тариф, например `249` при базовом тарифе 249 ₽ |

## 9. Возвраты

Крипта необратима, поэтому:

1. `/revoke <telegram_id>` — удалить подписку из панели (ключ перестанет работать).
2. Верни крипту вручную: @CryptoBot → My Apps → приложение → **Transfer** на `user_id`
   покупателя (его Telegram ID из заказа) — либо попроси у него адрес кошелька и отправь
   через Wallet → Send.

## 10. Переход на Stars в два клика

Если позже решишь вернуть Telegram Stars (например, для продаж внутри Telegram на iOS):
Railway → Variables → `PAYMENTS_MODE=stars` (переменные `CRYPTOBOT_*` можно оставить — они
не мешают). Крипта при этом выключится, но все настройки останутся в проекте.
