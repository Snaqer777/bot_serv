# Оплата картой внутри Telegram через @BotFather (ЮKassa)

Инструкция для режима `PAYMENTS_MODE=provider`: счёт выставляет сам Telegram, покупатель
платит картой **не выходя из чата**, деньги приходят на счёт магазина ЮKassa.

> ⚠️ **Правила Telegram.** Для цифровых товаров (VPN-ключей) внутри бота Telegram требует
> оплату в Telegram Stars. Этот режим технически рабочий и многие боты им пользуются, но
> формально он не соответствует правилам платформы — Telegram может прислать предупреждение
> и в крайнем случае ограничить бота. Решение за вами: если хотите минимизировать риск,
> оставьте Stars основным способом (`PAYMENTS_MODE=stars`), а карту принимайте по ссылке
> (режим `yookassa`, см. YOOKASSA.md) или на сайте.

## Как это работает

```
Клиент в боте          Telegram                         ЮKassa            Бот
───────────────────────────────────────────────────────────────────────────────────
«Тарифы» → тариф   →  sendInvoice(provider_token,        ────────►   заказ создан (pending)
                       payload = номер заказа)                        (ничего не выдаём)
жмёт «Оплатить»    →  форма оплаты в чате (карта)  ─────►  платёж
                   ◄─ pre_checkout_query ───────────────────────────── бот проверяет сумму и
                                                                       заказ → ok:true
оплатил            →  successful_payment ───────────────────────────►  бот выдаёт ключ
                                                                       в 3x-ui и присылает его
```

Ключевое: **ключ выдаётся только после `successful_payment`** — то есть после того, как
Telegram подтвердил оплату. Кнопка/форма выставляется лишь после проверок: заказ существует,
сумма совпадает, счёт ещё не оплачен.

## Шаг 1. Магазин в ЮKassa

1. Зарегистрируйтесь на [yookassa.ru](https://yookassa.ru/) и заполните анкету.
2. Для теста отдельный договор не нужен — тестовый токен в BotFather работает сразу.
3. Для боевого режима магазин должен быть активирован по договору (ИП/ООО/самозанятый).
4. **Важно для боевого режима:** попросите поддержку ЮKassa перевести магазин на
   **email-протокол** — напишите на `ecommerce@yoomoney.ru`, указав свой ShopID
   (без этого Telegram-платежи в боевом режиме могут не проходить).
5. Скопируйте **Shop ID** (и секретный ключ — он понадобится, если ЮKassa попросит
   подтвердить привязку).

## Шаг 2. Токен провайдера в BotFather

1. Откройте [@BotFather](https://t.me/BotFather) → `/mybots` → выберите своего бота.
2. **Bot Settings → Payments**.
3. Выберите **ЮKassa**.
4. Тестовый режим: **Connect ЮKassa Test** — BotFather выдаст готовый тестовый токен
   вида `381764678:TEST:100037` и данные тестовой карты.
5. Боевой режим: **Connect ЮKassa Live** → бот попросит `shopId` (из кабинета ЮKassa) и
   `shopArticleId` — **отправьте `0`** → вернётся боевой токен вида `x:LIVE:...`.
6. Токен всегда можно посмотреть заново: BotFather → ваш бот → Bot Settings → Payments.

Токен — это секрет: не публикуйте его и не пересылайте в чатах (он даёт право выставлять
счета от вашего магазина).

## Шаг 3. Переменные Railway

| Переменная | Значение | Обязательно |
|---|---|---|
| `PAYMENTS_MODE` | `provider` | да |
| `PAYMENT_PROVIDER_TOKEN` | `381764678:TEST:100037` (тест) или `x:LIVE:...` (бой) | да |
| `TELEGRAM_SEND_RECEIPT` | `1` — передавать чек 54-ФЗ, `0`/не задано — не передавать | нет |
| `TELEGRAM_RECEIPT_VAT_CODE` | `1` (без НДС), `2` (0 %), `3` (10 %), `4` (20 %), `5`, `6` | нет |

Про чек 54-ФЗ:

- если фискализация **не** подключена — не задавайте `TELEGRAM_SEND_RECEIPT` (по умолчанию 0);
- если чеки делает ЮKassa («Чеки от ЮKassa») — тоже оставьте 0, сервис сформирует их сам;
- если чеки фискализирует **ваша** онлайн-касса — поставьте `TELEGRAM_SEND_RECEIPT=1`,
  бот передаст в ЮKassa состав чека и попросит у покупателя email для его отправки.

## Шаг 4. Проверка настроек

В боте (под админом):

- `/panel_debug` → пункт «Оплата»: `provider`, «Provider token: задан ✅ — тестовый токен 🧪»,
  строка про чек.
- `/payments` → режим, токен (тест/бой), выручка, последние заказы.
- `/start` → «Тарифы» — цены в рублях, при выборе тарифа Telegram покажет форму оплаты.

## Шаг 5. Тестовая оплата

1. `/start` → «💰 Тарифы» → выберите тариф. При тестовом токене бот сначала пришлёт
   подсказку: «🧪 Тестовый платёжный режим…».
2. Telegram покажет счёт «Оплатить 249 ₽» (цена зависит от тарифа).
3. Оплатите тестовой картой:

| Номер карты | Тип |
|---|---|
| `5555 5555 5555 4477` | Mastercard с 3-D Secure (основная тестовая) |
| `5555 5555 5555 4444` | Mastercard без 3-D Secure |
| `4111 1111 1111 1111` | Visa |
| `2200 0000 0000 0004` | Мир с 3-D Secure |

Срок — любой в будущем, CVC и код 3-D Secure — любые 3 цифры. Реальные деньги не списываются.

4. После оплаты проверьте:
   - бот прислал ключ `vless://…` сразу после оплаты;
   - `/profile` — подписка «Активна», срок из тарифа;
   - `/payments` — заказ «✅ оплачен» и попал в выручку;
   - в панели 3x-ui есть клиент `tg-paid-<telegram_id>` с лимитами тарифа.

5. Проверьте отказ: тестовая карта `5555 5555 5555 4592` (3-D Secure не пройден) —
   ключ выдаваться не должен, заказ остаётся неоплаченным.

## Шаг 6. Переход в боевой режим

1. Активируйте магазин ЮKassa по договору, попросите email-протокол (шаг 1.4).
2. В BotFather подключите **Connect ЮKassa Live** и получите токен `x:LIVE:...`.
3. В Railway замените `PAYMENT_PROVIDER_TOKEN` на боевой, перезапустите сервис.
4. Проверьте на реальной оплате самого дешёвого тарифа; при необходимости верните деньги
   в кабинете ЮKassa (Платежи → платёж → «Вернуть») и удалите подписку командой
   `/revoke <telegram_id>`.
5. Если чеки делаете сами — включите `TELEGRAM_SEND_RECEIPT=1` и, при необходимости,
   замените тестовый токен на боевой.

## Как бот защищает деньги

- Счёт выставляется только на известную сумму заказа из журнала (`/payments`).
- `pre_checkout_query` проверяет: заказ существует, сумма совпадает с заказом, счёт ещё не
  оплачен — иначе счёт отклоняется (`ok: false`).
- Ключ выдаётся ровно один раз: повторная доставка `successful_payment`, перезапуск бота и
  повторные попытки не продлевают подписку дважды (номер платежа фиксируется в заказе и в
  комментарии клиента панели).
- Если панель 3x-ui недоступна в момент оплаты, заказ помечается оплаченным, но не выданным,
  админу уходит предупреждение, а выдача автоматически завершится при повторной доставке
  платежа — деньги не теряются.
- Если Telegram не принял сообщение с ключом, ключ сохраняется в заказе и досылается;
  покупатель в любой момент может забрать его командой `/profile`.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `PAYMENTS_MODE=provider, но PAYMENT_PROVIDER_TOKEN не задан` | Токен не добавлен в Railway Variables |
| «Ошибка: PAYMENT_PROVIDER_TOKEN invalid» при выставлении счёта | Токен скопирован неполностью/от другого бота. Посмотрите заново: BotFather → Bot Settings → Payments |
| В боевом режиме платёж не проходит, хотя токен верный | Магазин ЮKassa не переведён на email-протокол — напишите на `ecommerce@yoomoney.ru` с ShopID |
| Оплата прошла, а ключа нет | Проверьте `/payments` и логи Railway: бот мог не получить `successful_payment` (в этом случае заказ останется «pending», напишите в поддержку с номером заказа — платёж виден в кабинете ЮKassa) |
| Ключ выдался, но сообщение не дошло | Пользователь может забрать ключ: `/profile`; бот дослает его при повторной доставке платежа |
| Нужны чеки покупателям | Включите `TELEGRAM_SEND_RECEIPT=1` (только при работающей фискализации) |
| Хочется вернуть деньги | ЮKassa → Платежи → платёж → «Вернуть», затем `/revoke <telegram_id>` в боте |

## Сравнение с другими режимами

| | `provider` (эта инструкция) | `yookassa` (ссылка) | `stars` |
|---|---|---|---|
| Где платит клиент | форма оплаты в чате | страница ЮKassa в браузере | в чате, звёздами |
| Деньги | сразу на счёт магазина | сразу на счёт магазина | Fragment → TON (мин. 1000 ⭐️, 21 день) |
| Правила Telegram | ⚠️ не для цифровых товаров | ⚠️ допустимо, если в боте есть оплата звёздами | ✅ единственный разрешённый для цифрового товара |
| Что настраивать | токен в BotFather | shopId + ключ + вебхук | ничего |

Подробности про ссылочный режим — в `YOOKASSA.md`, про Stars и общий обзор — в `README.md`.
