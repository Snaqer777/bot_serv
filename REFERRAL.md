# 🎁 Реферальная программа: «пригласи друга — получи дни»

Друзья приводят друг друга сами: пригласивший получает **дни подписки**, приглашённый — **дни к
первой оплате**. Деньгами бот не распоряжается, поэтому вывод средств не нужен — только продление
подписки.

---

## 1. Как это выглядит для пользователя

1. Пользователь открывает бота → **«🎁 Пригласить друга — +7 дней»** (или команда `/invite`).
2. Бот показывает личную ссылку вида `https://t.me/<бот>?start=ref_12345`, кнопки
   **«📤 Поделиться ссылкой»** и **«📋 Скопировать ссылку»**, а также статистику:
   сколько друзей пришло, сколько оплатило, сколько дней начислено и сколько копится.
3. Друг нажимает ссылку → бот приветствует его и сразу говорит: «Тебя пригласили, тебе
   +3 дня к первой оплате».
4. Друг покупает любой тариф:
   - друг получает **тариф + 3 дня** сверху (дни видны в сообщении об оплате строкой
     «🎁 Бонус за друзей»);
   - пригласившему начисляется **+7 дней**:
     - если у него есть активная подписка — сразу, и он получает уведомление с новой датой;
     - если подписки нет — дни попадают в **копилку** и автоматически прибавляются к его
       следующей оплате.
5. Если друг оплатил повторно или кто-то из друзей оплатил ещё раз — повторных начислений нет:
   бонус за друга даётся один раз.

## 2. Правила (защита от накрутки)

| Ситуация | Что делает бот |
|---|---|
| Свой же ссылка (`ref_<свой id>`) | Игнорирует: «Своя же ссылка не считается» |
| Приглашённый уже был в боте / уже оплачивал | Первое приглашение побеждает, повторно записать нельзя |
| Ссылка на того, кто не запускал бота | Ничего не записывает (неизвестный приглашающий) |
| Друг оплатил **до** перехода по ссылке | Бонус не начисляется (нет приглашения) |
| Повторный вебхук / повторная доставка платежа | Подписка не продлевается, бонус не удваивается |
| `/test_pay` и другие тестовые выдачи | Бонусы не начисляются: это не оплата |
| `REFERRAL_ENABLED=0` | Программа выключена: `/invite` честно об этом сообщает, ссылки не работают |

Дополнительно: бонус пригласившему засчитывается только если заказ создан **после** перехода
друга по ссылке — задним числом награда не выдаётся.

## 3. Сколько дней дарить

Настраивается переменными окружения (Railway → Variables):

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `REFERRAL_ENABLED` | `1` | `0` / `false` — полностью выключить программу |
| `REFERRAL_BONUS_DAYS` | `7` | Сколько дней получает **пригласивший** за оплатившего друга |
| `REFERRAL_INVITED_BONUS_DAYS` | `3` | Сколько дней получает **приглашённый** к первой оплате |
| `REFERRAL_STORE_FILE` | `data/referrals.json` | Журнал приглашений (кто кого позвал, копилка) |
| `BOT_USERNAME` | — | Нужен для ссылок. Если пусто — бот спросит username у Telegram сам |

Примеры «акций»: `REFERRAL_BONUS_DAYS=14`, `REFERRAL_INVITED_BONUS_DAYS=0` (друг ничего не
получает, бонус только пригласившему).

## 4. Что писать в инструкции пользователю

- Ссылку не нужно придумывать: она в `/invite`, кнопка «Скопировать» кладёт её в буфер.
- Бонус — это **дни**, а не деньги: их видно в `/profile` (дата окончания подписки).
- Если подписки нет, дни не сгорают: они копятся и добавляются к следующей оплате.
- Бонус начисляется после того, как друг **оплатил** тариф. Тестовый доступ бонусов не даёт.

## 5. Что происходит «под капотом»

- Журнал приглашений — JSON-файл `REFERRAL_STORE_FILE` (пишется атомарно, рядом с журналом
  заказов). На Railway без volume файл может обнулиться при передеплое — тогда статистика
  приглашений начнётся заново, но **подписки не пострадают**: сроки уже стоят у клиентов в
  панели. Для сохранности журнала подключите volume, например
  `REFERRAL_STORE_FILE=/data/referrals.json`.
- Продление подписки за друга идёт через тот же путь, что и обычное продление: клиент
  `tg-paid-<id>` в 3x-ui, срок считается **от текущего окончания** (если подписка ещё жива),
  в комментарии обновляется дата, а номер платежа сохраняется — защита от повторной выдачи
  не ломается.
- Если панель недоступна в момент оплаты друга, подписка другу не выдастся — уйдёт алерт админу
  и заказ можно выдать повторно; бонус пригласившему тогда начислится при успешной выдаче.
- Начисление и уведомления обёрнуты в try/except: сбой бонуса не отменяет выдачу ключа.

## 6. Проверка без денег

```bash
python tests/test_referral.py     # 48 проверок: ссылка → друг → оплата → бонусы
python tests/test_help.py         # 71 проверка: пошаговая инструкция и её кнопки
```

Вручную: `/invite` (своя ссылка + правила) → открыть ссылку вторым аккаунтом (в своём Telegram
это можно сделать через `t.me/<бот>?start=ref_<ваш id>`) → оплатить тариф (в тестнете Crypto Pay
или через `/test_pay`, который бонусов не даёт) → проверить дату в `/profile`.

## 7. Частые вопросы

**Почему у друга не появились бонусные дни?**
Он создал заказ раньше, чем перешёл по ссылке, или выдачу делали тестовым путём (`/test_pay`).
Ещё вариант — `REFERRAL_INVITED_BONUS_DAYS=0`.

**Почему у меня «В копилке: 7 дн.»?**
Активной подписки нет. Дни прибавятся автоматически при следующей покупке любого тарифа.

**Можно ли записать друга на другого пригласившего?**
Нет. Первое приглашение фиксируется; если нужно передать — удалите запись из журнала
`REFERRAL_STORE_FILE` (только для админа и вручную).

**Как посмотреть общую статистику программы?**
Команда `/invite` показывает личную статистику. Общие цифры (сколько приглашений, сколько
оплатили, сколько дней выдано) пишутся в лог и доступны в `/payments` (админ) через журнал
начислений `rewarded` в `REFERRAL_STORE_FILE`.

**Хочу выключить программу.**
`REFERRAL_ENABLED=0` → ссылки не работают, новые приглашения не пишутся, бонусы не начисляются.
Уже начисленные дни у пользователей остаются.
